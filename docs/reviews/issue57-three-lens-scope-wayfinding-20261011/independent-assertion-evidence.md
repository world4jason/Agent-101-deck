# rev12 簡報獨立審查

## 判斷

**以 107 頁作為一份必須從頭講到尾的課堂簡報，負荷偏高；但頁數本身不能證明教材過量。** Manifest 標示 95 頁主線、12 頁附錄，並非 107 頁都要求現場講授。八張 Exit Check 各自收束一章，附錄也有查閱用途；不宜只因總頁數大就一概刪除。

較有根據的負荷問題是：若把 95 頁主線全部當作連續投影片教完，有些頁在重述相近能力，或把工具概念、流程細節和練習題一起放進主線。尤其 P45–47 用三頁反覆呈現同一版本補驗狀態；P64–76 對交接、分工與流程原則連續展開；P85–92 又多次回到人員核對、補驗與放行。這些是可由頁面內容辨認的重複與切換成本，不是由「107」這個數字推算出來的結論。

按 Garner／Alley 的 Assertion–Evidence 判準，頁面應以一個可陳述的主張帶領視覺證據；Waterloo 的視覺輔助原則也要求素材幫助聽眾理解訊息。這些判準能指出標題、文字、圖像和資訊量的問題，**不能單獨證明某頁對特定班級必然多餘或必然必要**。[Garner 與 Alley 研究摘要](https://pure.psu.edu/en/publications/assertion-evidence-slides-appear-to-lead-to-better-comprehension--2/)、[Waterloo：Designing Visual Aids](https://uwaterloo.ca/centre-for-teaching-excellence/catalogs/tip-sheets/designing-visual-aids)

## 五項最嚴重問題（P1）與最小調整

1. **P26：流程圖承載太多訊息。** 頁面同時列 Goal、三張票、七個狀態及兩種退回路徑。最小調整：畫面只保留 #3 的主流程及兩種退回箭頭；其他兩張票與狀態細節移至講者筆記或 P93 查閱。
2. **P45–47：同一補驗證據拆成三頁近似重述。** P45 顯示各情境狀態，P46 呈現重複 Like 從 NOT RUN 到 PASS，P47 再以同一版本指紋重講。最小調整：合併 P46–47，在 P45 之後用一張前後對照呈現「同一版本、只新增一項證據」。
3. **P64–76：交接、分工、流程原則連續切換多次。** 這段包含單 Agent、拆 Chat、多 Agent、交接遺漏、流程選擇、工具方法、五項原則；概念總結和例子交錯。最小調整：保留 P68 的交接卡及 P77–81 的可操作原則；把多 Agent 利弊、配置和特定工具移到附錄，讓 P64 只負責引入交接問題。
4. **P85–92：人類決策與放行訊息重複。** P84 已說接受放行由人決定；P88、P91、P92 又從證據、審查配置和假設發布重述相近邊界。最小調整：主線留一個證據判斷活動（P88–90）及一個放行總結；P91 與 P92 移至附錄或講者備用頁。
5. **P6、P7 與 P84：職能接力／責任邊界多次概述。** P6 已列需求、輸入、交付、接受；P7 再詳述 Reviewer、QA、人類接受；P84 又以 Agent 角色重畫相近責任。最小調整：P6 聚焦人類職能，P7 聚焦各交付物的驗收問題，P84 只呈現「Agent 可承接哪些工作、人仍保留哪些決策」。

## Core 與 Optional 技術背景

**Core：**理解共同目標與範圍、拆成可交付工作、用 AC／範例表達可觀察結果、追蹤版本、區分實作／審查／驗證、核對版本與證據、辨認 NOT RUN、跨人或跨 Session 交接、依風險決定接受或退回。這些能力有明確的後續頁面或 Exit Check 承接。

**Optional：**GitHub issue 階層等特定工具配置（P14）、Sprint／Kanban 的方法比較（P27、29）、多 Agent 優劣與模型設定（P67、73–75）、TDD／BDD／Specification by Example 術語延伸（P97–102）、Blocked 模板、事故處理、六層架構與完整看板回顧（P103–106）。這些內容可供特定課程或工作情境選讀，不應推定所有學員都必須現場逐頁學完。

若課程只有一個短時段，建議先以 **約 30–45 張主講頁**作為編輯試排範圍，其餘改成練習、講者備用頁或附錄；這是便於安排試教的編輯建議，不是研究確立的頁數標準。真正範圍需看課程時長、學員背景、互動比例與示範是否現場執行。Waterloo 教學中心提供「50 分鐘約 12–20 張」的實務建議，但不應直接當成適用所有課程的硬性門檻。[Waterloo：Lecturing Effectively](https://uwaterloo.ca/centre-for-teaching-excellence/catalogs/tip-sheets/lecturing-effectively)

## 指定頁段必要性比較

- **P14：**能讓學員看到 parent issue 與子票的實際對應，但教學目標是拆票與依賴，不是 GitHub 操作。建議併入 P15 的工具例子或移附錄。
- **P25：**四類資訊的區分有助讀懂後續流程圖，且是獨立能力；值得留，但要減少定義文字並凸顯「四類不可互換」。
- **P28／29：**P28 教 WIP 的計數方式，是理解看板的必要基礎；P29 比較上限 1 與 2 的取捨，屬情境性方法選擇，適合附錄或選講。
- **P42–47：**P42 建立黑箱驗收觀念，P43 列出預期組合，P44 展示失敗修正，P45 指到實際紀錄；各頁能力不同，適合主線。P46–47 則是在同一 Version B 上更新補驗狀態，應合併，避免把一項證據變更講成三頁。
- **P64／68–76：**P68 交接卡和 P77–81 的五項可操作原則最直接服務「交接工作」能力。P64 可縮成一頁問題入口；P66–67、P73–75 是選配背景；P69–72 與 P76 的總結應收斂，避免風險列表和原則列表各自重講。
- **P85–90：**這組包含定方向、整理規格、交辦材料、核對完成宣稱、提出補驗要求和跨 Session 接續，是有順序的實作能力鏈，主線價值高。P86 的 AI 協助範例若時間不足可選講，但不應與 P101 同時完整演練。
- **P96–107：**P96 是附錄導覽，P107 是查閱能力 Exit Check；兩者功能不同，應保留。P97–104 是按需回查的方法和情境，不必全部講授。P105–106 技術背景較重，且看板與前文重疊，適合選讀。

八張章節 Exit Check（P08、P30、P38、P49、P54、P82、P95、P107）題目對應各章的學習能力；目前文字也要求先作答再揭露參考答案。**不建議以「形式重複」為由刪除**，但實際教學可視時間採口頭、紙筆或跳題方式。

## 下次新增內容的三條可驗收規則

1. **每張新增頁須有一個可檢查的學員能力主張。** 標題寫出結論或要學會的動作；若只是術語定義、背景補充或導航，標為附錄或移講者筆記。
2. **新增頁須指出相鄰頁不能教會的差異。** 編輯者需列出先備頁、此頁新增的能力，以及 Exit Check 或練習如何使用它；若只是同一例子改寫或重複狀態，先合併。
3. **每張頁須能指出視覺證據與可讀性檢查方式。** 主張由圖、流程、比較或可核對紀錄支持；文字細節不應只能靠縮圖閱讀。未以教室投影實測前，字級與對比標為待驗。
