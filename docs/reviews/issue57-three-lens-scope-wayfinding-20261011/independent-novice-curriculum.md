# Agent 101 rev12 教材審查

**審查範圍：**本機 `slides/index.html`、`drafts/rev12-review/manifest.json`、指定的 107 頁盤點文件及你附上的投影片縮圖。依 manifest，教材共 107 頁，主線 95 頁、附錄自第 96 頁起；案例是 #1 Like／Pass、#3 雙向配對、#2 配對列表。

**視角限制：**以下是模型依教材內容推演的零基礎學員視角，不是真人試教、使用者研究或可讀性測試。投影可讀性標為 **NOT RUN**；縮圖只能判斷整體層級與資訊密度，不能驗證教室後排的字級。Demo 的結論依頁面標示，不把教學假設說成實測。

## 審查結論

教材的核心學習路徑成立：先理解人如何分工與接受交付，再學怎麼定目標、寫票、留版本、實作與驗收，最後交辦 Agent 並由人按證據決定接受或退回。這符合「目標、教學活動、評量相互對齊」的設計原則；CMU Eberly Center 也建議按先備能力安排內容，並縮減與目標不符或重複的材料。[CMU：目標、評量與教學活動對齊](https://www.cmu.edu/teaching/assessment/basics/alignment.html) [CMU：安排課程內容與順序](https://www.cmu.edu/teaching/designteach/design/contentschedule.html)

**整份資訊有超載風險，但不能只因 107 頁判定超載。**主要問題是核心技能、選讀工具知識和重述內容混在同一條主線：C2 的 Ready／Kanban／WIP 概念較多，C5 的 Agent 背景與交接失誤分得過細，C6 又重畫一次工作流程。若每頁都講，零基礎學員容易失去「目前在處理哪張票、走到哪一站」的定位。建議把核心練習與必要評量留在主線，將工具選項、方法名稱與完整架構移至附錄或講者 Notes。

這也符合多媒體學習的 coherence、segmenting、signaling 原則：減少與當前學習目標無關的資訊、讓學習者分段處理內容，並明確提示重點。[多媒體學習原則整理](https://teaching.pitt.edu/wp-content/uploads/2023/03/multimedia-principles-checklist.pdf) Waterloo 的教學指引也提醒，投影片是視覺輔助，不是講稿；畫面應突出主點，細節用講述或 Notes 補足。[University of Waterloo：Designing Visual Aids](https://uwaterloo.ca/centre-for-teaching-excellence/catalogs/tip-sheets/designing-visual-aids)

## Kanban、Git、Agent 的定位缺口

教材已有章節導覽列，但新手未必知道「人類工作流程」「看板欄位」「Git 版本狀態」是不同層次。明確的連續頁跳接包括：

- **P14–P15 → P16–P21：**先介紹 issue／Backlog／Ready，再回頭討論需求歧義、角色與範例。初學者可能不知道票已進 Backlog，為何又回到需求討論。建議在 P16 加一句投影提示：**「票還在 Backlog；這一步是在補清楚條件，尚未開始 Dev。」**
- **P24–P30 → P31–P37：**從 Ready／WIP 直接切到檔案版本、commit 和 branch。學員可能把「票移到 Dev」和「Git branch」當成同一狀態。P31 應明示：**看板回答工作進度；Git 記錄程式版本。**
- **P35–P37 → P39–P45：**branch／PR／merge 後進入 Dev、Review、QA，但課堂上不易知道 PR 是版本交接物，Review／QA 是工作流程中的檢查站。建議 P39 明示當前工作票與所在欄位，並標註「PR 是交付物；Review／QA 是後續檢查」。
- **P54 → P55–P63：**從人的發布決策突然進入 Agent、session 和 context，缺少一個可辨認的交接點。建議章首投影：**「流程已到人工驗收；接下來用 Agent 接手 Dev 工作，仍沿同一張 #3 票與版本證據前進。」**
- **P72–P82 → P83–P93：**先講 Agent 流程與原則，後面又回到工作票、看板和放行總結，容易被理解為新流程或另一套看板。建議 P83 指明是同一張 #3 Ticket 的 Agent 交付與人類驗收段。

**投影導覽提案：**在章節轉場頁使用一條單一主流程位置條：

> 人定義問題 → 寫票 → 留版本 → 實作與檢查 → 人放行 → Agent 接手／人驗收

只在轉場頁標目前位置及接下來一站，例如「目前：#3 已 Ready；接下來看版本如何分開與送審」。到 Kanban 頁才顯示欄位，到 Git 頁才顯示版本圖。無需每張投影片同時放兩種流程，也不必增加一張永久佔版面的雙流程圖。

## 建議縮短版主線 Outline

**示例假設：**Workshop 長度未知。以下以一場約 **3 小時、含兩次短休息** 的入門工作坊規劃主線頁數；頁數是設計區間，不是課程時數的實測保證。若場次更短，先減少工具細節與講述示例，不先刪掉練習或 Exit Check。CMU 的評量原則要求讓評量真的檢查預期能力，並給學員足夠練習與回饋。[CMU：評量設計](https://www.cmu.edu/teaching/designteach/syllabus/newcourse/assessments.html)

|---|---|---:|
| C0 人類合作 | 能說明一個工作從需求到接受有哪些責任與交接物 | 5–6 |
| C2 想法到 Ready | 能把熟悉問題寫成一張含範圍、成功條件及核對方式的票 | 10–12 |
| C1 版本協作 | 能解釋 commit、branch、PR、merge 在版本接力中的用途 | 5–6 |
| C3 實作與驗收 | 能看預期／實際／未測證據，判斷通過、退回或補驗 | 7–9 |
| C4 放行與完成 | 能分辨一張票 Done 與整體 Goal 達成，指出放行決策人 | 3–4 |
| C5 Agent 演進 | 能列出交給 Agent 的版本、票、限制及必要交接材料 | 6–8 |
| C6 Agent 交付 | 能寫交辦、要求補驗，並在證據不足時停止 | 8–10 |
| **合計** | **含各章轉場及 Exit Check** | **44–55 頁** |

**附錄：**建議保留 P97–P106 作按需查閱；P96 做索引。P107 僅在需要評量「能否在附錄找到方法」時保留。

縮短版不是把原頁逐一替換成同數量新頁。優先方向是：

- 將 P05 併入 P06；P10／P11、P16／P17、P22／P23、P46／P47、P52／P53、P88／P89 分別整併，減少重述。
- 將 P27、P29 的流程比較／WIP 取捨，以及 P60–P67、P73–P76 的 Agent 背景與工具選項移出主線。
- 保留 C0、C2、C3、C6 的能力檢核與學員練習；不要以「頁數多」為由一併刪除八張 Exit Check。
- 保留 P94 的遷移活動；它讓學員把案例能力用在自己的工作上，屬於目標對齊的實作，而非多餘案例。

Exit Check 作為低風險提取練習有合理性，但每章都逐題完整播放解答可能佔用很多時間。可按課堂長度安排代表題作答、同伴互核，再由講師揭示關鍵判準。不要只留問題、不給回饋。

## Demo A／B／B-pre／B-post：證據邊界

- **Demo A** 在 P58 是預先交付並規劃版本的教學示範。
- **Demo B** 在 P59 是修正、重測並交回證據的另一版本示範。它不能被說成現場前後測實驗。
- P46–P47 的 **B 補驗前（B-pre）** 明確標示單向與雙向規則已有結果，重複 Like 是 **NOT RUN**，且 UI／整合也未驗。
- **B 補驗後（B-post）** 只新增重複 Like 規則層證據；反向方向、雙方未 Like 及 UI／整合仍是未測。
- P92 是「若略過人類放行」的假設推演。P104 明示 App 尚未真實部署；P106 也說明看板 Done 的回顧是條件式推演。

因此可說「教材示範如何交付與補驗」；不可說「真人試用證明有效」「產品已通過整合測試」或「App 已上線」。

## 三個短練習

| 練習 | 做法 | 對應頁／能力 |
|---|---|---|
| **把 Ticket 放到正確欄** | 給一張有「AC 已寫、QA 尚未跑」的票，請學員選 Backlog、Ready、Dev、Review、QA 或 Product Check，並說明下一步。再給一張 QA 發現實作錯誤的票，請指出退回哪欄。 | P15、P24、P26、P41、P44；辨認工作狀態及退回路徑 |
| **Git 現在在做什麼** | 顯示「commit → push branch → 開 PR → review → merge」五張卡，請學員排序，並分別回答「留下版本」「分享版本」「請人審查」「回共同版本」發生在哪一步。 | P33–P37；辨認版本動作與票的狀態是不同概念 |
| **何時人要退回** | 給出預期 0 筆、實際 1 筆、版本 B、另一個情境 NOT RUN 的結果，請學員寫一句退回指令，說明要補哪個情境、沿用哪個 AC、哪些事項不得自行宣布完成。 | P45–P49、P88–P92；依證據要求補驗、暫停或退回 |

**Notes 建議內容：**講者逐頁轉場、縮寫首現解釋、預期回答與常見誤解、Demo A／B 的版本及證據邊界、實際操作時的命令／入口、活動答案和時間建議、投影無法完整顯示的次要細節。學員接受工作所需的 **AC、版本、預期／實際與未測結果仍應留在畫面或工作票**；不要把關鍵判斷條件藏進講者 Notes。
