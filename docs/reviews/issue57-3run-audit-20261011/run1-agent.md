## 判定

**P73–P107 的 G3／G4：PASS（限 AI 依實際 DOM 與當前 Chrome 截圖做文字、圖片審查）。**真人試教、教室投影與現場閱讀狀況均 **NOT RUN**；因此這個 PASS 不代表學員已能順利理解或操作。

整段主線大致接得上：先談 Agent 的流程與分工，再示範交辦、查證據、要求補驗，最後回到人作放行決定。沒有看到必須判退的 P0/P1。以下列出會影響零基礎理解或誤判驗收狀態的問題。

## P1

- **P74｜model、effort 的定義與工作例子不足以支撐中間結論。**可見文字先以「簡單、中等、困難」列出工作，接著直接說「同一個 model／同一個 effort」，再推到「設定開高／開低」的時間成本與可靠性；零基礎讀者可能把這理解成固定的選擇規則，而不是待評估的取捨。建議在例子旁補一句判斷依據，例如「同一設定是比較情境；是否調整，需看模型能力、成本及實際結果」，並把 effort 說成「可用的推理強度選項，依產品與模型而異」。無需再加一整套模型選擇流程。

- **P76｜五項原則是摘要，但讀者此時還看不到對應的逐項說明。**頁面說「英文名稱及詳細說明保留在後續頁」，但在截圖中，下一頁 P77 只開始談共用工作紀錄，尚未對五項原則逐項回指；讀者可能把這五列當成已經教完的檢查表。建議在五列上標出後續頁碼，或在下一段逐項沿用相同名稱，讓摘要與講解能對照。

- **P89–P90｜互動要求有先作答與揭露答案，但答案揭露後的實際補驗結果仍容易被讀成「整體通過」。**P90 將「Version B 補驗後」及「工具結果：PASS」放在顯眼位置；雖然同頁和 P91 都寫明 UI／產品串接仍 NOT RUN、不能宣稱全部通過或自行發布，但讀者需要自行把局部 PASS 和未測範圍合併判斷。建議讓結果標籤直接寫成「重複 Like 規則測試：PASS」，並讓「UI／整合：NOT RUN」與其並列。這會保留補驗的前後互動，也更清楚地界定人尚未放行。

- **P93、P106｜Human Gate 的位置前後一致，但初學者可能把看板狀態與決策點混為一談。**P93 說「Human Gate 在 Product Check → Done 間」；P106 同時顯示 Product Check 中的 #3 與「待人放行」。文字已說 Gate 不另增看板狀態，然而圖面位置仍容易讓人以為 Gate 是一個狀態欄。建議在 P106 直接標註「Human Gate：欄外決策點」，並以連線指向 Product Check 和 Done 之間。

## P2

- **P73｜Workflow、Agent、Single-agent、Multi-agent 同頁比較，且有兩組不同問題。**圖的分組已有幫助，但結論「Workflow 和 Agent 可以一起使用；人數、WIP 另計」資訊較密。建議授課時口頭明確收束成兩個判斷：「誰決定下一步？」與「有幾位執行者？」避免學員把 Workflow 和 Agent 當成互斥選項。
- **P75–P76｜Grill Me、Superpowers、AC、Ticket 等詞密集出現。**P75 已用箭頭和文字說明流程；零基礎讀者仍可能不知道 Grill Me／Superpowers 是方法名稱，而非角色。最小改法是在第一次出現處加「兩種工作方式的名稱」，不用展開工具背景。
- **P82、P95、P107｜Exit Check 的答案有收合，但題目仍含部分情境線索。**P82 的 WIP 題明示「已核准上限調為 2」，因此不是直接給答案，但已提示作答方向；P95 Q2 直接指出重複 Like 是 NOT RUN；P107 Q1 把要查的方法與情境寫在同題。作為課後檢查可以接受；若目的是測能否獨立回想，建議把「提示」放進可選展開，題面只留任務。
- **P97｜三種規則表達方式的比較清楚，但 GWT 縮寫可能對初學者仍陌生。**前面的 P86 已寫出 Given–When–Then，故非完全未解釋；仍可在 P97 首次可見處標作「Given–When–Then（前提－事件－結果）」幫助快速回想。
- **P83–P94｜小字和文字密度是投影可讀性的風險。**截圖中若干說明、版本標識與來源字樣明顯偏小，尤其 P87、P89–P90；這不等於應機械減字或換卡片。建議在真人試教／投影時特別確認關鍵狀態「PASS／NOT RUN／不合併、不發布」能否從教室後排讀到。
