## P0／P1：需要先處理

**P0：沒有。** 靜態畫面中沒有看到會讓學員直接學錯流程、或關鍵放行證據明顯消失的問題。

**P1：沒有足夠證據列出必須先改的阻斷項。** 有幾處值得改善掃讀和流程表達，列在 P2；其中 P24 的人工放行是否保留，建議講者在試教時確認。

## P2：改善建議

- **P2**：After 把開場收成一個標題和八格路線圖，能看出「先交付、再驗收」的大方向。不過八格權重接近，五秒掃讀容易先看到一排卡片，未必立刻明白本課主張。可考慮在標題或副標直接說出核心主張，並讓「人類交付給 Agent 驗收」成為清楚入口；八個章節仍可保留為導航。

- **P5、P9、P31、P39、P50、P55、P83、P96**：After 的章節 overview 改成標題、目前位置、三步流程和學完能做什麼，畫面比 Before 更有主次，也更容易沿箭頭掃讀。比對 P5、P31、P83，After 把原本的問題卡改成清楚的三步，學習路徑比較直接。P39、P50 也保留了 Dev／Review／QA 與風險判斷的不同工作，沒有把它們混成同一件事。
  **仍有閱讀節奏問題**：P9、P31、P83 等頁標題與三步流程的結構相似，連續觀看時容易像同一種版型換字；P55、P96 的三步也偏抽象，學員可能需要聽講者補充才懂「Context 與 Session」或「Blocked 與事故」具體怎麼操作。建議優先把最抽象的一步改成可觀察的行動或結果，不必強求每頁用相同模板。

- **P2**：After 的八格章節地圖可當索引，但各格同權重、內容又密，對零基礎學員不是很容易快速定位。可在視覺上區分目前要走的主線與後續章節，或先突出最重要的交付路徑。這是閱讀引導改善，不代表八章本身需要刪減。

- **P23 AC／AT**：After 把 AC 收斂成「單向 0→0、雙向 0→1、重複 Like 不增加」，AT 用前置狀態、操作、預期結果呈現，判斷條件比 Before 更可驗證。底部仍保留 **Evidence｜尚未執行（NOT RUN）**，也說明 DoD 是共用完工要求；證據與未執行狀態沒有消失。建議講者口頭點明「AC 是驗收條件、AT 是測試情境、DoD 是共用完工要求」，避免新手把三者當成同一層。

- **P24 Ready**：After 清楚呈現「Ready、WIP 仍是 0」以及能否實作、能否驗出、是否缺資料三個檢查點，掃讀比 Before 快。不過這頁沒有明確指出**誰決定放行**；標題又是「Ready：可以開工」，初學者可能以為條件成立就自動開始。建議在頁面上補一個短句或標示決策者，明確說明是否有人確認後才開始。這是目前最值得在試教中確認的流程歧義。

- **P75 Grill Me／Superpowers**：After 保留兩種做法，但「Grill Me」和「Superpowers」兩張等大的彩色卡，學員先看到的是方法名稱，較難立即理解兩者在什麼條件下使用。卡片內已提到一種由人確認需求、一種由人設計流程與協作；可把這個選擇條件提到頁首或作為兩欄的小標，讓比較的目的先於術語出現。

## 前後比較判斷

- **P5**：Before 的三張問題卡同時搶注意力；After 的三步箭頭和完成條件形成較清楚的掃讀路徑。
- **P23**：After 把 AC 判斷與 AT 操作分開，測試是否執行也仍標為 NOT RUN；可讀性和證據狀態都有保留。
- **P24**：After 更快交代 Ready 與 WIP 狀態，也集中呈現三個檢查問題；但放行者不明確，仍需補足流程決策資訊。
