## Whole Picture 先於細節｜教學敘事契約

**開場的目標是提供一份 Advance Organizer，不是規定教材只能有四／五／八個章節。** 現有八章仍完整保留，若發現先備知識或教學練習不足，可以另行提案增補／調整章節；不能只為了符合固定數字而改編。

- **第 2 頁：**先顯示目前完整章節路線及各章要回答的問題，告訴學員「為什麼先理解人類流程，之後才理解 Agent 與人的驗收」；附錄以參考資料呈現。
- **人類職能與交付（C0–C4）：**同一 Matching App 從人類的分工、Idea／Goal、票、版本、Dev、Review、QA 走到放行；先懂工作本身為何存在，避免提前背 Agent 名詞。
- **Agent 演進與交付（C5–C6）：**同一張工作票先讓一人＋一 Agent 跑完交付和補驗，再討論分工；映回人類職能，最後由人核對 Goal／AC／版本／證據接受或退回。
- **章節封面／導航：**繼續顯示目前八章；每章標示它在整份課程中的位置，允許回到第 2 頁 Whole Picture。八章是小節清單，不是八個互不相干的目標。
- **八張 Exit Checks：**每章考學員能做什麼；能回答各章的問題並說明前後承接，才符合學習脈絡。真人試教前不得宣稱效果已驗證。
- **章節增補原則：**先指出當前學習路線中的具體缺口（前提／例子／練習／轉場），再討論如何補足；不要只因為希望項目變多或變少而增加／刪減章節。

**跨頁 Review 時必問：**站在完全沒讀過 README 的學員立場，只看第 2 頁能否說出整份課想解決什麼？現在進到某章時能否知道「為什麼學這章」？後面介紹 Agent 時，能否指出它接手的是哪項原本人類工作？
