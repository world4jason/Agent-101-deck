## 1. 本輪已記錄的決定

- 先講全由人類完成時的角色、版本與開發驗收流程，後面才加入 Agent，對照接手方式與新問題。
- Top down＋lead by example；用同一配對 App 的三張票，先出現問題，再帶方法與名稱。
- 四項延伸進主線：AI 協助 Example Mapping、廚房比喻、範例夠不夠、好範例取捨；其餘完整方法先放附錄。
- 本輪只做可審閱的逐頁編排。每頁列：沿用／調整／新增、來源、暫定標題、教學作用／帶入方式／帶走重點、投影片主句、圖面承載方式與下一頁轉場。
- 原 55 頁全部保留。沿用可以移位，但不減少原頁；調整是待審的內容提案，尚未改現有檔案。
- 不指定新的視覺風格、配色、框架或動畫。圖面描述是內容擺放建議；實際版面另議。舊頁內容與既有圖保留，三個主句是講解焦點，不是刪掉其他內容的指令。
- 所有配對行為、驗證輸出、版本 A／B 均為教學示意；不得冒充現有 App 的實測證據。

## 6. 調整頁的邊界與要核對的內容

- P06／P25／P26：人類流程先說清 Goal Check→人工放行→merge／release／上線檢查；與後面 P51 的固定 Gate 一致。
- P08／P10／P11／P12／P13：沿用原圖並補案例；保留版本、分工、送審、整合的全部教學目的，不變成 Git 指令課。
- P11：「尚未 commit」不是宣稱所有未提交資料永遠無法救回；只說本次 Git 提交歷史未記錄它。
- P17：保留三票與資料流；開發順序另行說明，不以 MECE 要求互不合作。
- P19：只把 Owner 點名的不自然標題改成工作導向說法，原看板內容保留。
- P22／P24／P27：Dev 自測、CI、Review、QA 的工作分清；CI 執行取決於設定，QA 不等於只按 checks。
- P30／P32／P33／P34／P43：限定教學情境，避免 Chat／Agent 互斥、compact 必然失憶、新 session 無法讀共享資料、設定必然導致特定價格／品質等說法。
- P36：workflow／single／multi 保留兩軸，不把流程控制說成數量等級。
- P42：因章節調整，以問題名稱取代舊段號；五原則內容保留。
- P45：PO／PM Agent 可整理與提出接受建議；固定的人類 Gate 不被角色名抹去。
- P53：附錄封面範圍擴大，原 P54／P55 不刪。
- P49：依Owner後續回饋改為三段責任；九站原表留在rev10，不再放進rev11主畫面。
