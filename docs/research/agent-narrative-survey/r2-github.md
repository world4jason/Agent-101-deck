# 第 2 輪研究：從 chat 的限制，講到 workflow 與多 Agent

## 四、兩段投影片的修正敘事

**第一段〈大家怎麼用 chat；問題何時出現〉——我的教學建議。**先呈現一個熟悉的畫面：在同一個 chat 說「幫我把這張 ticket 做完」。接著沿用已教的看板，逐格追問：需求釐清在哪裡？Dev 的產物在哪裡？誰按什麼標準做 PR Review 和 QA？下次開新 session，接手者讀什麼？這樣六個問題會從**同一件工作的經過**浮現，而不是先丟出 single／multi-agent 術語。這種「先看任務步驟」的橋接，對應 [DeepLearning.AI Module 1〈Task decomposition〉](https://www.deeplearning.ai/courses/agentic-ai)及 [Microsoft 第 07 課〈Task Decomposition〉](https://github.com/microsoft/ai-agents-for-beginners/blob/main/07-planning-design/README.md)；具體內容例子見 [Datawhale 1.6 節](https://github.com/datawhalechina/agentic-ai/blob/main/1.%20Agentic%E5%B7%A5%E4%BD%9C%E6%B5%81%E7%AE%80%E4%BB%8B%5BIntroduction%20to%20Agentic%20Workflows%5D/1.6%20%E4%BB%BB%E5%8A%A1%E5%88%86%E8%A7%A3-%E8%AF%86%E5%88%AB%E5%B7%A5%E4%BD%9C%E6%B5%81%E7%A8%8B%E6%AD%A5%E9%AA%A4%5BTask%20decomposition-%20identifying%20the%20steps%20in%20a%20workflow%5D.md)。

**第二段〈把流程交給 Agent〉——我的教學建議。**先讓觀眾看到同一張 ticket 在看板上移動，且每關都有輸入、產物與檢查結果；然後才問：「哪些關卡可以由 AI 執行？哪些需要另一個角色來檢查？哪些仍由人決定？」至此再介紹單一 Agent、專門 Agent、模型路由與交接。這與 [Microsoft 第 07 課從子任務走向指派](https://github.com/microsoft/ai-agents-for-beginners/blob/main/07-planning-design/README.md)，以及 [Hugging Face Unit 2.1 先試單一 Agent、再因具體瓶頸拆分](https://huggingface.co/learn/agents-course/unit2/smolagents/multi_agent_systems)的順序相符。

最後可用一句話避免四個詞混成同一組選項：**chat 是人怎麼提出與討論工作；workflow 是工作怎麼往下一關走；single／multi-agent 是誰執行；model／effort 是每一關用多少能力與成本。**這是我的分類歸納。[Hugging Face Unit 1〈Agency spectrum〉](https://huggingface.co/learn/agents-course/en/unit1/what-are-agents)甚至把能使用工具的客服 chatbot 列為 Agent 例子，因此不宜說「chat 一定不是 Agent」。
