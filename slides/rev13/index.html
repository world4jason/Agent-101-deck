Insight：Epic／Story／Task 是課程採用的分類方式，不是每個 GitHub repo 的內建固定類型。

Go：從 Goal 沿分解關係讀到工作票，再追到 AC 與驗收材料。

講者筆記

Insight：Issue、Project、PR 可承載協作內容，但不是 Git Commit；GitHub 連接工作紀錄和版本審查。

Go：沿文件連線找建立、更新、審查與留存位置。

Evidence scope：生命週期示意，不代表文件已建立或已更新。

Data：Goal 是產品 Outcome；Stage Target 是本站工作；AC 描述工作範圍內的行為；AT 是檢查情境；Exit 決定交棒；DoD 是共用完成條件；Evidence 記錄實際觀察。

Insight：一個層級的 PASS 不會自動證明其他層級完成。

Go：請學員把一個問題放到能回答它的層級。

Evidence scope：術語邊界概念圖；未展示 Matching 測試結果。

下一站：辨認 Git、GitHub 與各協作物件。

Git 保存版本歷史，GitHub 連接工作票與程式送審。

Git 管版本歷史；Issue 與 Project 管工作和狀態，PR 連起票與版本差異。

講者筆記

Data：Git 管版本歷史；Repo 容納受版本控制的檔案；Branch／Commit 表示隔離修改與歷史節點；Issue／Project 記工作與狀態；PR 承載版本送審、討論與 Checks；Merge 整合獲准變更。

Insight：GitHub Issue 不是 Git Commit，PR 也不是 Ticket；PR 是文件討論與版本差異交會的位置。

Go：請學員沿工作紀錄軌和版本軌，指出兩軌在哪個協作物件相連。

Evidence scope：物件關係概念圖，沒有建立真實 Repo、Branch 或 PR。

下一站：把版本變更讀成可回查的分支路徑。

講者筆記

Data：一條抽象版本路徑從 Repo 的既有版本分出 Branch，Commit 記下修改，PR 呈交差異供審查，經授權後才 Merge。

Insight：版本路徑可以比較、回查與回復；PR 開啟或審查通過都不等於已 Merge。

Go：沿路徑指出哪些物件代表隔離、記錄、審查與整合。

Evidence scope：版本歷史示意，不對應 Matching 第一版或修正版 或真實 PR。

下一站：認識 Agent、Session、Chat 與 Workflow 的差別。

Agent 能在受委託範圍內執行，但不能替人決定放行。

講者筆記

Data：Chat 是互動介面；Session 是一次工作脈絡；Agent 是能依指示使用工具的執行者；Workflow 是多步工作流程。

Insight：這些名詞不互相等同。Agent 可讀取指定工作契約、在授權範圍內執行並回報；範圍改變與最後放行仍由人決定。

Go：指出一個可能受委託的工作，並追問其工作票、驗收條件與停止點。

Evidence scope：概念預告；不表示已執行單 Agent／多 Agent 工作，也不展示測試結果。畫面只留一行情境預告：「有人想做配對」。

講者筆記

Data：Target 是決定下一個要處理的使用者問題與方向；Input 是問題、觀察、機會與限制；活動包含探索選項和成功訊號；Output 是 Goal／Proposal 與未決假設。

Insight：產品 Goal 尚待形成；沒有方向確認與共同紀錄，就不能假設工作已 Ready。

Go：先找出誰確認方向，再追到 Goal 或 Proposal Issue 的記錄位置。

Evidence scope：Stage 定義；沒有 Matching 決議或 Issue 建立事件。

下一站：在 Backlog 的 Refinement 把方向變成可交辦工作。

Refinement 把 Goal 拆成可估算、可驗證的工作。

票可以拆分並釐清，仍要符合 Ready 條件才可接手。

講者筆記

Data：Input 是已決定的 Goal、限制、依賴和未決問題；活動包括界定範圍、拆 Epic／Story／Task、釐清 AC／AT、證據、風險與負責角色；Output 是 Parent／Child Tickets 及未決清單。

Insight：Refinement 在 Backlog 進行，拆票完成不會自動把票移到 Ready。

Go：檢查是否仍有阻礙；處置未決項後，再由 Ready Check 判定能否接手。

Evidence scope：Stage 定義；沒有宣稱 Matching 子票或 Project 欄位已建立。

下一站：Ready Check 確認這張票是否具備開工條件。

講者筆記

Data：PO／Dev 主責確認；QA 協作檢查範圍、AC、可測性、依賴與責任；Output 是可接手的 Ready Ticket 與明確接手者。

Insight：Ready 是允許開始工作的條件，不代表已經開始或已完成測試。

Go：逐項核對 Required Ready 條件，再判斷是否允許拉進 Dev。

Evidence scope：Stage 定義；畫面上的 Backlog／Ready 是流程說明，不是某張真實票的狀態。

下一站：Dev 在核准範圍內產生版本與自測紀錄。

Dev 在核准範圍內實作並交出版本與自測紀錄。

自測紀錄能交給審查者參考，但不等於獨立 QA 完成。

講者筆記

Data：Input 是 Ready Ticket、設計／AC、共同 Repo 與 停止條件；Dev 建 Branch、修改、Commit、自測並記錄未完成項；Output 是版本、修改摘要與自測紀錄。

Insight：版本需能對回核准票；Developer 自測不替代 Reviewer 或 QA 的獨立責任。

Go：確認交接內容包含修改版本、自測範圍與未驗項，再進 PR Review。

Insight：PR Review 查改動、範圍與風險；它不取代依 AC 執行的 QA，也不表示已 Merge。

Go：先處置重大意見，確認待審改動可交付 QA，再交接測試證據。

Evidence scope：Review 站定義；沒有虛構任何真實 PR 歷史。

下一站：QA 用可重跑的方式核對版本行為。

講者筆記

Data：Input 是版本、AC／AT、測試資料與環境；QA 記錄預期與實際，標示 PASS、FAIL 或未測；Output 是可追溯的測試紀錄與補測請求。

Insight：沒有執行的案例保持未測；結果只支持它實際檢查的版本與範圍。

Evidence scope：QA 方法概念；Matching 第一版與修正版結果會在後面展示；介面、完整流程、上線與產品目標測試若被提及，皆未測。
